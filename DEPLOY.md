## 3. Миграции БД на проде **[ты]**

Накатить миграции на боевую БД **по порядку имён файлов**. Все идемпотентны —
можно прогнать весь каталог целиком, уже применённые ничего не сломают
(проверено тройным прогоном всех семи миграций на чистой БД 2026-08-19,
включая новую `2026-08-18-indexes.sql`: ошибок нет, набор из 15 таблиц
и 6 индексов `idx_active_*` совпадает):

```bash
for f in db/migrations/*.sql; do
  echo "applying $f"
  mysql -u USER -p БАЗА < "$f"
done
```

Что именно должно быть на проде:

| Миграция | Без неё ломается |
|---|---|
| `2026-06-18-orders-schema.sql` | заказы (`orders`/`order_items`), поля упаковки товара |
| `2026-06-19-order-access-token.sql` | защита ссылок на заказ/счёт (IDOR) |
| **`2026-07-02-reviews.sql`** | **отзывы: блок на главной, `review_add.php`, `admin/reviews.php`** — обязательна |
| `2026-07-03-settings.sql` | цены материалов калькулятора (`admin/settings.php`) |
| `2026-08-18-admin-roles.sql` | роли `superadmin`/`viewer` в админке — **см. отдельный шаг ниже** |
| `2026-08-18-indexes.sql` | скорость каталога: составные индексы `products` + `ANALYZE TABLE` |
| `2026-08-18-offer-carts.sql` | сохранение «сборной корзины» расчётов (`includes/api.php`) |

Разбор каждой миграции и откат — в `db/README.md`.

### 3.1. Проверить результат `2026-08-18-admin-roles.sql` глазами ⚠️

Миграция не только расширяет ENUM ролей до
`('superadmin','admin','manager','viewer')` — вторым запросом она **поднимает
старейшего активного администратора до `superadmin`**, но только если суперадмина
в таблице ещё нет (`UPDATE ... WHERE role='admin' AND is_active=1 AND NOT EXISTS
(...superadmin...) ORDER BY id ASC LIMIT 1`). Это сделано, чтобы после ужесточения
прав система не осталась без владельца: `edit_users`/`delete_users` есть только
у `superadmin`.

На проде состав таблицы `admins` не такой, как на деве, поэтому **после накатки
посмотреть, кого именно повысило**:

```sql
SELECT id, username, role, is_active FROM admins ORDER BY id;
```

- Если `superadmin` достался не тому аккаунту (например, старому техническому
  или уволенному) — переназначить вручную:
  `UPDATE admins SET role='admin' WHERE id=<чужой>;`
  `UPDATE admins SET role='superadmin' WHERE id=<нужный>;`
- Если суперадмина нет вообще (все `admin` были `is_active=0`) — назначить руками,
  иначе управлять учётками в админке будет некому.

### 3.2. `2026-08-18-indexes.sql` — что ожидать

Добавляет 6 индексов на `products` (`idx_active`, `idx_active_created`,
`idx_active_sold`, `idx_active_price`, `idx_active_stock`, `idx_active_category`)
и делает `ANALYZE TABLE products`. Схему не меняет, только `KEY`; идемпотентна
(наличие индекса проверяется по `information_schema.STATISTICS`). На боевом объёме
каталога выполняется быстро, но это `ALTER TABLE` — накатывать в окно с низким
трафиком. `ANALYZE TABLE` обязателен: без него оптимизатор какое-то время
игнорирует новые индексы (кардинальность `NULL` сразу после `ALTER`).

### 4.1. `www/includes/config.php`

Проверить/заполнить в боевом `www/includes/config.php`:
- **`SELLER_*`** — все заполнены (иначе футер падает Fatal).
- **amoCRM** — токен истёк 31.05.2026, **перевыпустить** (`AMOCRM_ACCESS_TOKEN`).
- **ЮKassa** — `YOOKASSA_SHOP_ID` / `SECRET`, настроить webhook в ЛК на
  `/api/payment_callback.php`.
- **Email** — рабочий MTA на проде (иначе письма не уходят).
- `SUPPORT_PHONE` / `ADMIN_EMAIL` — реальные (проверить, что и в шапке, и в футере).

**Новые константы, которых в старом боевом config.php нет** — добавить из
`www/includes/config.example.php`:

| Константа | Зачем |
|---|---|
| `LOG_DIR` (`dirname(ROOT_PATH) . '/logs'`) | каталог логов вне веб-корня — см. п. 4.3 |
| `FNS_API_KEY` | поиск реквизитов по ИНН (api-fns.ru) для счетов, из админ-инструмента |
| `YOOKASSA_VAT_CODE` | **ставка НДС в чеке 54-ФЗ**; значения: `1` = **без НДС** (значение по умолчанию в примере), `2` = 0 %, `3` = 10 %, `4` = 20 %, `5` = 10/110, `6` = 20/120 |

⚠️ **`YOOKASSA_VAT_CODE` выставить по своей системе налогообложения.** По умолчанию
стоит `1` — «без НДС». Если продавец на ОСН и в футере/договоре заявлен НДС, а тут
останется `1`, чек 54-ФЗ уедет покупателю с неверной ставкой.

Незаполненные секреты больше не молчат: `config_warn_placeholders()` (вызывается
в конце `config.php`) на каждом запросе проверяет `RECAPTCHA_*`, `AMOCRM_*`,
`YOOKASSA_SHOP_ID`/`SECRET_KEY`, `FNS_API_KEY` на остаток плейсхолдера `ВАШ_…`
и пишет в лог строку `config: не заполнены секреты (…)` — не чаще раза в час
(маркер `config-warn.stamp` в `LOG_DIR`). **После выката заглянуть в
`logs/app-error.log`** — если строка есть, соответствующая интеграция работает
заглушкой (reCAPTCHA без ключа пропускает всех, ЮKassa не создаёт платёж).

### 4.2. Telegram-бот: секрет вебхука + перерегистрация ⚠️

Бот теперь **fail-closed**: `tg/bot.php` принимает только POST с валидным
заголовком `X-Telegram-Bot-Api-Secret-Token` (сверка `hash_equals`). Пока секрет
не задан и вебхук не перерегистрирован, **бот отвечает 403 на все апдейты** —
заявки из Telegram не доходят.

1. Добавить в боевой `www/tg/config.php` константы из `www/tg/config.example.php`
   (файл не в git, старая боевая версия их не содержит):
   - `TG_WEBHOOK_SECRET` — сгенерировать: `php -r "echo bin2hex(random_bytes(32));"`
     (разрешены `A-Z a-z 0-9 _ -`, длина 1..256);
   - `TG_WEBHOOK_URL` — `https://zippaket-optom.ru/tg/bot.php`
     (необязательна, это же значение — дефолт в `setwebhook.php`);
   - `TG_STATE_TTL_DAYS` — срок хранения файлов состояний `tg/users/`
     (необязательна, по умолчанию 30; 152-ФЗ — там имя и телефон).
2. **Перерегистрировать вебхук из CLI на проде** (из CLI секрет не спрашивается):

   ```bash
   php www/tg/setwebhook.php
   ```

   Скрипт зовёт `setWebhook` с `secret_token` и `drop_pending_updates=true`.
   По HTTP тот же скрипт теперь требует секрет:
   `curl "https://<домен>/tg/setwebhook.php?secret=<TG_WEBHOOK_SECRET>"`.
3. Проверить: написать боту в Telegram, пройти сценарий заявки — сообщение должно
   дойти, в `logs/tg-bot.log` не должно быть строк про отказ по секрету.

### 4.3. Каталог логов `LOG_DIR` **[ты]**

Лог приложения (`includes/api.php` → `app-error.log`) и лог бота
(`tg/bot_lib.php` → `tg-bot.log`) пишутся в `LOG_DIR` — каталог `logs/`
**рядом с `www/`, вне веб-корня**, чтобы лог нельзя было скачать по HTTP.

- Каталог должен существовать и быть **доступен на запись** пользователю
  веб-сервера/PHP-FPM. Код пытается создать его сам (`@mkdir(..., 0750, true)`),
  но на shared-хостинге прав на каталог уровнем выше веб-корня может не быть —
  тогда создать вручную.
- Если каталог недоступен, падения не будет: код молча откатывается на системный
  `error_log` веб-сервера. Это удобно, но означает, что **отсутствие
  `logs/app-error.log` после выката — сигнал проверить права**, а не признак,
  что всё хорошо.
- Убедиться, что `logs/` не смотрит в веб (не под `www/` и не симлинк из него).

## 5. Смоук-проверка после выката

- Главная, каталог, карточка товара, корзина, checkout, калькулятор — открываются, светлые, иконки на месте.
- `/sitemap.xml` отдаётся.
- **Оптовая цена доходит до счёта**: положить в корзину количество выше порога
  (`WHOLESALE_TIERS`, напр. 25 000 шт) — цена за штуку в корзине, в заказе
  и в счёте должна совпадать со ступенью, а не быть розничной.
- Товар без цены («Цена по запросу») в корзину не кладётся — на карточке
  «Запросить цену» вместо «В корзину».
- Тестовый заказ → уведомления (Telegram/email/amoCRM) приходят.
- **Telegram-бот отвечает** (см. п. 4.2 — вебхук перерегистрирован с секретом).
- **Заявка из калькулятора реально сохраняется**: отправить расчёт и проверить,
  что появилась строка в `calculations` (а сборная корзина — в `offer_carts`).
  Раньше здесь была заглушка, возвращавшая `success:true` без записи.
- Админка `/admin/` — вход, «Расчёты», «Настройки» (сменить временный пароль!),
  «Пользователи» открывается под суперадмином (см. п. 3.1).
- **`logs/app-error.log` пишется** и в нём нет строки
  `config: не заполнены секреты (…)` (см. п. 4.1).
- **Консоль браузера пуста от ошибок CSP** (`Refused to load/apply…`) на главной,
  каталоге, карточке товара, checkout и в `/admin/statistics.php` (там Chart.js).
  CSP переписана — проверить, что FontAwesome, Google Fonts, reCAPTCHA,
  Яндекс.Метрика и Chart.js грузятся.
- 301-редиректы ведут на ЧПУ, а не на «сырые» адреса:
  `http://www.zippaket-optom.ru/product/1` → `https://zippaket-optom.ru/product/1`
  (а НЕ на `…/product.php?id=1`); `https://zippaket-optom.ru/index.php` → `/`.
